# Backtest results

Rolling-origin (expanding window) backtest on Online Retail II daily unit sales.
Generated by `python -m forecast.backtest`. Only numbers from this file should be reported.

| Setting | Value |
|---|---|
| Products | top 50 by revenue before the first cutoff |
| Folds | 23 (cutoff every 7 days) |
| Horizon | 28 days |
| Cutoffs | 2011-06-09 to 2011-11-10 |
| Evaluated days | 2011-06-10 to 2011-12-08 |
| Forecast points per model | 32,200 |

| Model | WAPE | MAE (units/day) |
|---|---|---|
| moving_average_28 | 97.2% | 36.65 |
| moving_average_7 | 102.4% | 38.64 |
| seasonal_naive | 110.8% | 41.81 |
| naive | 171.9% | 64.85 |

Notes:
- WAPE = sum of |error| / sum of actual units, pooled over all products and folds. MAPE isn't used because most product-days have zero sales.
- Ranking products by revenue before the first cutoff keeps future sales out of product selection.
- 2011-12-09 is excluded: the data ends mid-day, so it's a partial day.
- Saturdays have almost no orders in this dataset, so weekly patterns matter.
- Large wholesale orders cause spikes; they are kept, not clipped.
